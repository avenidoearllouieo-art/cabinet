# TapTrack Render Deployment

The root `render.yaml` is now the temporary free-testing Blueprint. It configures only the React `frontend`, Django `backend`, and a free Render PostgreSQL database. `cabinet`, Raspberry Pi services, and ESP32 firmware are not included. The free resources use distinct `*-free-test` names so syncing this Blueprint creates separate test resources instead of downgrading or detaching storage from production resources. The previous paid production configuration is preserved separately in [`render.paid.yaml`](render.paid.yaml); do not sync that file for free testing.

## Free Testing Configuration

**Django API**

- Root directory: repository root (`.`), because `requirements.txt` is at the repository root.
- Build command: `bash backend/build.sh`
- Start command: `mkdir -p "${DJANGO_FILE_UPLOAD_TEMP_DIR:-/tmp/taptrack-tmp}" && python backend/manage.py migrate --noinput && gunicorn --chdir backend config.wsgi:application --bind 0.0.0.0:$PORT`
- Settings / WSGI: `config.settings` / `config.wsgi:application`
- Plan: `free`; no persistent disk is configured.

On the free plan Render does not support a pre-deploy command, so the existing migration command runs at service startup before Gunicorn. Migrations are repeatable schema updates; they do not import, flush, or delete database records.

**React static site**

- Root directory: `frontend`
- Build command: `npm ci && npm run build`
- Publish directory: `dist` in the Dashboard (`frontend/dist` in the root Blueprint, which is repo-root-relative).
- The existing `BrowserRouter` is supported by a `/*` rewrite to `/index.html`.

The API uses `DJANGO_FILE_UPLOAD_TEMP_DIR` only for transient multipart request buffers. Persisted uploads use private S3-compatible object storage and remain behind Django's authenticated, role-checked preview/download endpoints. Keep the bucket private, disable public access, and issue a least-privilege storage key for this application. The API hostname is automatically added to `ALLOWED_HOSTS`. If deployed NFC readers are part of the test, add `TAPTRACK_NFC_DEVICE_MAP` as a secret using the existing test-device mapping. `DEVICE_API_KEY` is only for development mock mode; it is not used as a production device credential. Add custom hostnames through `DJANGO_ALLOWED_HOSTS` if needed.

### Tigris Bucket CORS

Configure CORS on the private `taptrack-files` bucket to allow direct signed part uploads and signed GET playback. Replace `<actual-taptrack-web-origin>` with the exact origin shown for the existing Render static site and keep local origins only for development:

```json
{
	"CORSRules": [{
		"AllowedOrigins": [
			"https://<actual-taptrack-web-origin>",
			"http://localhost:5173",
			"http://localhost:5176",
			"http://localhost:5177"
		],
		"AllowedMethods": ["PUT", "GET", "HEAD"],
		"AllowedHeaders": ["*"],
		"ExposeHeaders": ["ETag", "Content-Length", "Content-Range", "Accept-Ranges"],
		"MaxAgeSeconds": 3600
	}]
}
```

Do not add `*` to `AllowedOrigins` and do not enable public bucket access. `ExposeHeaders: ["ETag"]` is required because the browser sends each completed part's ETag back to Django.

The Blueprint uses `sync: false` for origin/URL/reader values. Render prompts for them on initial Blueprint creation; for an already-created Blueprint, configure them in the Render dashboard.

## Media Migration And Retention

- Create the bucket before deployment. Configure the API's new `AWS_*` environment values in the Render dashboard under the `taptrack-api` service, and verify private access before allowing uploads.
- For an existing persistent filesystem deployment, keep its existing disk attached until migration is verified. Set `DJANGO_LEGACY_MEDIA_ROOT` to the old media directory and run `python backend/manage.py migrate_legacy_media --dry-run`; inspect the summary, then run `python backend/manage.py migrate_legacy_media`. The command preserves storage keys and source files, skips keys already in the bucket, and can report missing local objects with `--fail-on-missing`. The paid Blueprint deliberately retains the existing disk for this migration window; remove it only in a later approved deployment after confirming the copy.
- For the prior free configuration, the legacy root was `/tmp/taptrack-media`. Attempt the copy from the running service before it restarts, if the files remain there. Objects already lost from Render's ephemeral filesystem cannot be reconstructed from their database rows; restore from a backup or request re-upload.
- New activity files, submissions, temporary submissions, discussion attachments, profile images, and access-log images use the configured private bucket. Incoming request buffers may still use ephemeral `/tmp`, which is expected because they are not saved uploads.
- Existing objects are not automatically copied at startup. Complete and verify any migration before removing an old persistent disk. Database filenames/storage keys are not rewritten.
- Render PostgreSQL backup/retention depends on the selected database plan. Follow the plan's backup policy before applying migrations.
- Large student videos up to 5 GiB go directly from browser to Tigris in 32 MiB parts; they do not pass through Render's request-body limit. The current backend defaults allow 10 GiB across at most five retained/pending files. Tigris documents standard S3 multipart operations and a 5 TB object ceiling, but account quotas, bandwidth, and service-plan limits still apply. The actual cap tested here is through mocked multipart calls, not a live 500 MB+ video transfer.
- Run `python backend/manage.py cleanup_tigris_multipart_uploads --dry-run` before scheduling daily cleanup through an existing operations scheduler; the command aborts expired tracked sessions and old orphaned MPUs without touching completed objects.

## Local Safety

Without `DATABASE_URL`, Django continues to use local `backend/db.sqlite3` and `backend/media`; `DJANGO_MEDIA_STORAGE_BACKEND=filesystem` is used for local development. The Render configuration does not include `cabinet`, Raspberry Pi services, or ESP32 firmware.
