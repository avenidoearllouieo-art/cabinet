# TapTrack Cabinet UI

## Raspberry Pi preparation

This is the official Raspberry Pi Cabinet touchscreen UI, built with React 19 and Vite 8. In hardware mode it reads verification results from the Pi-local scan bridge; it does not submit real NFC UIDs to Django.

Requirements: Raspberry Pi OS 64-bit recommended, Node.js 22.12 or newer, npm 10 or newer, a browser for the LCD, and network access to the computer running Django.

Check versions:

```bash
node --version
npm --version
```

Use `/home/pi/apps/taptrack-cabinet` on the Pi for the full repository. Clone the repository there, then run:

```bash
git clone <your-repository-url> /home/pi/apps/taptrack-cabinet
cd /home/pi/apps/taptrack-cabinet/cabinet
npm install
```

Install the Pi tools and Python runtime:

```bash
sudo apt update
sudo apt install -y git curl python3 python3-venv chromium
```

Install Node.js 22 with nvm:

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
source ~/.nvm/nvm.sh
nvm install 22.12.0
nvm alias default 22.12.0
```

Create `.env.production` in `/home/pi/apps/taptrack-cabinet/cabinet`:

```env
VITE_NFC_MODE=hardware
VITE_NFC_BRIDGE_URL=http://127.0.0.1:5001/api/scans
VITE_WEB_APP_BASE_URL=http://192.168.1.100:5176
```

Replace `192.168.1.100` with the LAN IP of the computer running the TapTrack Portal. Do not use `localhost` or `127.0.0.1` in this variable because the student's phone would resolve those addresses to itself. Build and run:

```bash
cd /home/pi/apps/taptrack-cabinet/cabinet
npm run build
npm run preview
```

Open `http://127.0.0.1:4000` in the Pi browser. Optional Chromium kiosk mode:

```bash
chromium --kiosk --app=http://127.0.0.1:4000
```

Start the Portal so phones on the same Wi-Fi can reach it:

```bash
cd /home/pi/apps/taptrack-cabinet/frontend
npm install
npm run dev -- --host 0.0.0.0
```

The QR should contain a URL like `http://192.168.1.100:5176/register?token=<temporary-token>`. Find the host computer's LAN address with `ipconfig` on Windows or `hostname -I` on Linux. The temporary token is generated by Django; the raw NFC UID is never included.

On the Django computer, configure `backend/.env` with `DEVICE_API_KEY`, add the Django server IP to `DJANGO_ALLOWED_HOSTS`, allow TCP port 8000 through the firewall, and restart Django. The device key belongs only to the Pi listener; do not put it in Cabinet `VITE_` variables or the browser bundle.

The NFC service uses only Python's standard library, so no Python package installation is required. From the copied repository, run it separately from the Cabinet UI:

```bash
cd /home/pi/apps/taptrack-cabinet/pi_service
export TAPTRACK_NFC_MODE=production
export TAPTRACK_NFC_BIND_HOST=127.0.0.1
export TAPTRACK_NFC_PORT=5000
python3 nfc_service.py
```

The current production mode reports that no reader adapter is configured. The hardware-specific reader adapter must be added after the teammate confirms the exact reader model and library. The service must never receive `DEVICE_API_KEY` and must never call Django.

For local mock development, use `npm run dev` from `cabinet`. The Vite development proxy may use `DEVICE_API_KEY` from the local backend environment; it is not included in production browser assets. Hardware mode reads only from the local bridge.

The hardware bridge contract is `GET http://127.0.0.1:5001/api/scans?after=<event_id>&limit=50`. The Pi listener must start that bridge after completing its existing Django verification request. The browser never sends the UID to Django and never receives the device API key.

## React Compiler

The React Compiler is not enabled on this template because of its impact on dev & build performances. To add it, see [this documentation](https://react.dev/learn/react-compiler/installation).
